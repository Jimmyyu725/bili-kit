# Bilibili 评论 500 条上限设计

## 目标

Caption Lite 在 Bilibili 视频页后台读取评论时，主评论与楼中楼回复合计最多保留和复制 500 条。达到上限后立即停止继续请求，避免额外流量和无限加载。

## 计数与停止规则

- 一条主评论计为 1 条，每条楼中楼回复也计为 1 条。
- 所有已去重的主评论和回复合计不得超过 500 条。
- 每批数据合并时只接收剩余容量允许的部分，保证任何快照都不会出现第 501 条。
- 一旦计数达到 500，立即结束主评论或楼中楼分页，不再发出新的评论请求。
- 不足 500 条且服务端已无后续分页时，仍按原有逻辑标记为全部加载完成。

## 状态与复制文案

- 快照增加 `limitReached`，区分“服务端全部加载完成”和“达到本地上限”。
- 达到上限时，状态提示为“已达到 500 条上限，停止加载。”
- 达到上限时，按钮显示“复制 500 条（上限）”，避免误称已复制视频的全部评论。
- 未达到上限时保持现有文案：加载中显示“复制当前 N 条”，自然完成显示“复制全部 N 条”。
- 用户在加载过程中复制，不会中止后台任务；只有达到上限或自然完成才停止。

## 数据流

1. 加载器为当前视频建立内存中的评论树。
2. 每个主评论页按顺序规范化、去重并加入，加入前检查剩余容量。
3. 主评论页已使总数达到 500 时，直接返回带 `limitReached: true` 的最终快照。
4. 若主评论不足 500，再逐页读取缺失的楼中楼回复；每页同样只加入剩余容量允许的回复。
5. 楼中楼阶段达到 500 时立即返回上限快照。
6. 控制器将 `limitReached` 传到页面状态，侧边栏据此显示上限文案。

## 异常与边界

- 单个 API 页面就返回超过剩余容量的数据时，只保留恰好填满 500 条的前半批数据。
- 重复评论不消耗容量。
- 达到上限后不再触发游标异常重试、下一主评论页或下一楼中楼页。
- 页面切换、取消任务、网络重试和登录错误行为保持不变。
- 复制内容格式和评论顺序保持不变。

## 验证

- 测试主评论批次在 500 条处精确截断，且不请求下一页。
- 测试楼中楼批次补足到 500 条后精确停止，且不请求下一页或后续楼层。
- 测试控制器保留并发布 `limitReached`，显示正确状态和复制后提示。
- 测试侧边栏按钮在达到上限时显示“复制 500 条（上限）”。
- 运行全部自动化测试，并在 Mac 插件目录更新后重新加载扩展验证。
