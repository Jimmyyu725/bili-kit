# Bilibili 全部评论复制与字幕面板顺序设计

## 目标

为 Caption Lite 的 Bilibili 视频页增加“一键复制全部评论”，同时把嵌入式字幕面板稳定放在“弹幕列表”上方。第一阶段不改变 YouTube 行为。

成功标准：

- 用户点击一次“复制全部评论”后，页面保持当前位置，不发生自动滚动或跳动。
- 扩展在后台分页读取全部主评论以及每条主评论的全部回复，完成后一次性写入剪贴板。
- 加载过程中持续显示已读取数量；加载失败时不把不完整结果冒充为全部评论。
- Bilibili 页面上的字幕面板显示在“弹幕列表”卡片之前，并继续支持展开、折叠、字幕跳转和下载。

## 方案选择

采用 Bilibili 评论接口后台分页，不模拟页面滚动，也不局限于页面已经渲染的评论。

扩展在页面主世界中复用当前 Bilibili 会话，通过现有的视频信息接口取得 `aid`，读取 WBI 签名信息，然后分页请求主评论和缺失的楼中楼回复。该方案不移动页面且比 DOM 选择器更完整；代价是 Bilibili 内部接口改变后可能需要适配。

不采用以下方案：

- DOM 自动滚动并点击“展开回复”：会移动界面，速度慢，并且高度依赖页面结构。
- 只读取当前 DOM：无法满足“全部评论”。

## 组件与数据流

### 评论数据模块

新增可独立测试的评论辅助模块，负责：

- 生成 WBI 请求签名。
- 规范化 Bilibili 主评论和回复数据。
- 按 `rpid` 去重，并保持主评论顺序和回复顺序。
- 把结果格式化为纯文本。

文本格式如下：

```text
[主评论用户名] 主评论正文
  ↳ [回复用户名] 回复正文

[下一位用户名] 下一条主评论
```

评论正文中的换行会保留，回复使用缩进表达所属关系，不附加点赞数等未请求的元数据。

### 页面主世界

`bilibili-main.js` 接收“加载全部评论”命令并执行分页：

1. 确认当前仍是同一个 Bilibili 视频。
2. 取得视频 `aid` 和当前会话的 WBI 签名材料。
3. 串行读取主评论页面，避免并发触发限流。
4. 对回复数量大于已内嵌回复数量的主评论，继续分页读取楼中楼。
5. 每取得一批数据就发送进度；游标结束后发送完整结果。

视频切换或新任务开始时，旧任务失效。接口报错、权限不足、限流或响应结构异常时终止任务并返回错误，不复制部分结果。

### 扩展隔离世界与面板

`content.js` 在页面主世界和扩展 UI 之间传递开始、进度、成功与失败消息。原生 Chrome 侧边栏通过 service worker 转发命令；网页内嵌面板直接复用同一状态处理函数。

面板底部新增“复制全部评论”按钮：

- 仅在当前来源为 Bilibili 时显示并启用。
- 加载时显示“读取评论 N 条”，并禁止重复启动。
- 完成后写入剪贴板，显示“已复制 N 条评论”。
- 失败时恢复按钮并显示可重试的错误信息。

评论内容只在本次操作的内存中存在，不写入 `chrome.storage`，不上传到任何外部服务。

## 字幕面板位置

Bilibili 使用 `#danmukuBox` 定位弹幕区域。现有实现会在存在播放列表时优先锚定播放列表容器，因此截图中“弹幕列表”出现在字幕面板之前。

新实现始终以弹幕区域的布局容器为首选锚点：

- 在该容器顶部预留与字幕面板等高的空间。
- 绝对定位字幕面板到预留空间顶部，使其视觉顺序为“字幕列表 → 弹幕列表 → 其他侧栏内容”。
- 展开或折叠时重新计算预留高度。
- 页面导航、容器替换或面板移除时恢复原始内边距，避免污染 Bilibili 布局。

继续使用隔离的 Shadow DOM，不把面板直接交给 Bilibili 的页面框架管理，以降低页面重渲染时被删除的风险。

## 错误处理与边界

- 没有可用评论：复制空结果之前提示“未找到评论”。
- 需要登录、被限流或接口拒绝：显示 Bilibili 返回的可读错误，并允许重新点击。
- 视频切换：取消旧结果，防止把上一个视频的评论复制到剪贴板。
- 剪贴板写入失败：保留已取得的文本于当前内存，将按钮改为“再次复制”；下一次点击直接重试写入，不重新请求评论，也不自动下载文件。
- 评论数量很大：保持串行分页和进度显示，不人为滚动页面，不声明固定数量上限；浏览器或接口明确失败时停止并报告。

## 测试

- 单元测试：WBI 签名的确定性、评论规范化、去重、嵌套回复和纯文本格式。
- 交互测试：Bilibili 状态下显示按钮，YouTube 状态下隐藏；加载、成功、失败时按钮和提示正确。
- 消息测试：开始、进度、完成、失败和视频切换失效路径。
- 布局回归：Bilibili 锚点优先使用弹幕容器，展开和折叠时更新预留高度；YouTube 定位保持不变。
- 完整验证：运行 `npm test`，并在 Mac Chrome 的真实 Bilibili 视频页手动确认页面不滚动、回复完整、剪贴板内容和面板顺序。
