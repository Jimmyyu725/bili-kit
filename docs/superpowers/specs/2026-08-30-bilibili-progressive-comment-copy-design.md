# Bilibili 持续加载与随时复制评论设计

## 目标

Caption Lite 在用户打开 Bilibili 视频后立即自动加载评论，不需要先点击复制按钮。加载任务在扩展隔离内容脚本中持续运行，页面不滚动、不跳转。

用户可以在加载期间随时点击按钮，复制当时已经加载的评论快照。复制操作不暂停、不取消、也不重新开始加载；扩展继续读取，直到确认全部主评论和楼中楼回复均已完成。

成功标准：

- 进入 Bilibili 视频后自动开始读取评论。
- 每完成一页主评论或楼中楼回复，立即更新可复制快照和已加载数量。
- 加载中按钮显示“复制当前 N 条”；完成后显示“复制全部 N 条”。
- 点击复制只复制当前快照，完成后继续后台读取。
- 中间游标缺失、重复、网络波动或限流时不丢弃快照，也不把部分结果标记为全部。
- 切换视频后旧任务立即失效，新视频自动开始新的加载任务。

## 方案选择

采用“单个持续加载任务 + 内存快照”方案。

不采用定时从第一页重新抓取：它会重复请求、浪费时间，并使数量在每轮之间不稳定。不采用 DOM 自动滚动：它会移动页面并依赖易变的页面结构。

## 组件与数据流

### 评论加载器

`bilibili-comment-loader.js` 继续在扩展隔离世界中串行读取固定 Bilibili API：

1. 获取视频 `aid` 和 WBI 签名材料。
2. 按游标逐页读取主评论。
3. 每页合并、按评论 ID 去重后，生成一次不可变文本快照。
4. 主评论完成后，只为回复数量大于已内嵌数量的主评论继续读取楼中楼。
5. 每批楼中楼合并后再次生成快照。
6. 全部完成时发送 `complete: true` 的最终快照。

快照包含：

- `pageKey`：视频与分 P 身份。
- `count`：当前已经实际取得的主评论与回复总数。
- `text`：按现有格式生成的完整当前文本。
- `complete`：是否已经确认所有分页结束。
- `phase`：`roots`、`replies` 或 `complete`，用于可读状态提示。

加载器不会把尚未取得的回复计入 `count`。如果某条主评论已有部分回复，当前快照会包含这些已取得回复；后续快照会继续补齐。

### 自动加载与快照控制器

评论控制器拆分为两个互不阻塞的动作：

- `startLoading()`：视频打开后自动调用一次，负责启动持续任务并接收快照。
- `copyCurrent()`：按钮点击时只读取控制器内存中的最新快照并写入剪贴板。

控制器为每个视频任务保存：加载代次、`AbortController`、最新快照、加载状态和最后一次复制结果。复制成功后不清除快照，不改变加载代次，也不终止网络请求。

同一视频重复触发自动加载时复用正在运行或已经完成的任务，不从头请求。Chrome 的顶层导航与 History API 导航消息会使旧任务代次失效并中止请求；内容脚本随后为新 `pageKey` 自动启动任务。

### 面板状态

按钮与提示按以下规则显示：

- 尚未取得评论：按钮显示“正在加载评论…”，暂时不可复制。
- 正在加载且已有内容：按钮显示“复制当前 N 条”，可以随时点击。
- 刚复制但仍在加载：提示“已复制 N 条，仍在继续加载…”，按钮保持可用。
- 全部完成：按钮显示“复制全部 N 条”，提示“全部评论已加载”。
- 暂时重试：保留“复制当前 N 条”，提示“加载暂时停在 N 条，正在自动重试…”。
- 复制失败：保留快照，下一次点击仅重试剪贴板，不重新请求评论。

原生侧边栏和网页内嵌面板继续消费同一个紧凑状态；完整评论正文不进入 `chrome.storage`。

## 游标异常与重试

错误“评论分页游标异常”的直接触发条件是：加载器在 `is_end` 仍为 `false` 时遇到空的 `next_offset`，或遇到已经使用过的游标。对 Mac 当前打开的两个视频进行接口诊断时，匿名请求均正常到达 `is_end: true`，因此尚未取得触发报错那一次登录态响应的原始形态。已经确认的本地根因是：代码把上述游标状态一律当作致命错误，并且只在最终完成时交付文本，导致此前已经加载的结果也无法复制。

新实现把这类响应视为可恢复的暂时停滞：

- 保留全部已加载线程和最新快照。
- 对当前页重新请求，并使用新的 WBI 时间签名。
- 退避间隔依次为 2、4、8、15、30 秒，之后保持 30 秒。
- 一旦取得新评论或新游标，重试计数立即清零。
- 页面保持打开且任务仍属于当前视频时持续重试，不把停滞误报为完成。

HTTP 429、服务器错误和暂时性网络错误采用同一退避策略。明确不可恢复的响应（视频不存在、身份无法解析、WBI 材料结构无效）显示错误并停止；用户刷新页面后会建立新任务。

## 数据与隐私

评论请求仅访问源码固定的 `https://api.bilibili.com` 路径。完整评论及快照只保存在当前内容脚本内存和用户剪贴板中，不写入扩展存储、不下载文件、不上传第三方。

Bilibili 页面主世界不接收评论请求、进度或结果，无法伪造待复制文本。

## 测试

- 加载器：主评论多页、楼中楼补齐、每批快照、最终完成快照。
- 游标恢复：空游标、重复游标、下一次请求恢复、退避上限和进展后重置。
- 控制器：页面打开自动启动、加载中复制快照、复制后继续加载、完成后复制全部。
- 控制器：没有快照时不可复制、剪贴板失败后重试不重新请求。
- 导航：快速 A → B → A 使旧任务失效并中止，回到 A 后启动新任务。
- UI：按钮文字、可用状态、数量和提示随 `loading`、`retrying`、`complete` 变化。
- 回归：字幕面板仍在弹幕列表上方，YouTube 行为不变。
- 完整验证：Atlas 与 Mac 均运行 `npm test`，并在 Mac Chrome 真实 Bilibili 视频页确认自动加载、随时复制和持续增长。
